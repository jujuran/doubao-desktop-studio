# Doubao Desktop Studio

> 作者：[jujuran](https://github.com/jujuran) · [官方仓库](https://github.com/jujuran/doubao-desktop-studio)<br>
> **本软件在 GitHub 免费提供，无需付费购买。如果你是花钱买到的，可以到 GitHub 免费下载最新版。**

一个本地优先、跨平台的豆包账号工作台。每个账号使用独立的 Electron `persist:` Partition，Cookie、LocalStorage、缓存和登录状态不会互相混用。

## 当前能力

- 独立账号空间与持久化登录
- 登录后自动确认明确 UID，登录失效时更新账号状态，并阻止重复添加同一账号
- 账号本地备注修改、活动窗口状态和最后确认时间
- 关闭窗口后保留登录状态，账号不会长期占用渲染进程
- 缓存清理不清除登录状态
- 本地 SQLite 账号元数据、任务和设置
- 支持 JSON/Markdown 整套分镜导入，也可逐镜创建和编辑
- 每个分镜可选择三种首帧来源：本地图片、提示词生成、无首帧（纯文生视频）
- 批量导入时可按 `01.png`、`分镜1.png`、`shot_01.jpg` 等名称自动匹配本地首帧，并预览缺图、重图、多余图片及画幅差异
- 提示词生成的首帧完成后自动下载全部候选到项目目录，在工作台审核并锁定一张后才解锁视频阶段；也可把本地图片导入为待审核候选，不会直接覆盖已锁定首帧
- 重新生图只在实际提交后改变阶段状态；取消、未提交即关窗或后续生成失败时，已锁定首帧仍可继续用于视频
- 打开视频页时自动上传已锁定首帧并填入提示词、模型、时长和画幅；最终生成按钮默认人工点击，也可在设置中开启“核对一致后自动点击”
- 自动识别生图/视频开始、二次确认、安全确认、预计等待时间、完成和页面报告的失败；生成文件回到工作台审核，视频不通过时移入项目的“作废”子文件夹
- 视频完成后优先识别预览面板和视频卡片附近带“下载”提示的官方图标；预览刚打开而入口尚未出现时会等待并自动重试 3 次，最终失败会暂停并静音视频；按官方返回地址标记水印版本，若返回带水印地址会自动重试一次，不绕过平台权限或水印策略
- 视频失败后仍会继续监听；也可“重新检查并下载”、导入手动下载的视频候选，或重新启动监听
- 项目级全局提示词：可共用，也可分别覆盖生图与视频阶段；按“全局在前、分镜在后”合成
- 旧版五项“风格锁定”会迁移成未启用草稿，需人工确认后生效
- 本地管理角色/宠物定妆图、场景参考图和风格参考图，并锁定项目模型与画幅；生图时会按顺序自动上传角色参考图，视频阶段暂不额外上传项目参考图
- 每个项目可独立设置输出目录；新项目批量导入时默认使用所选素材文件夹，旧项目保持原目录且不会自动搬移已有文件
- 根据账号今日生图/视频用量，分别均衡分配待执行任务
- 账号页展示并可校准今日使用记录，适合测试期补录工具外消耗
- 记住最近使用的账号、模型、时长和画幅
- 一键打开指定账号的豆包生图/视频页，自动填入提示词并同步复制到剪贴板
- 应用内存、进程数和活动账号窗口监控
- 可在设置页迁移本地数据目录，账号登录状态、数据库和设置会一起迁移
- 本地滚动诊断日志与脱敏诊断报告导出
- 同时打开的豆包窗口推荐 3 个，可设置 1–20 个
- Windows x64 与 macOS x64/arm64 构建配置

当前版本不会自动注册账号、处理验证码、导入密码或规避平台限制。请仅使用本人拥有或获授权的账号，并遵守平台规则。

## 分镜导入示例

```markdown
格式版本：1
项目名称：柯基短片
全局提示词：吉卜力风格宠物动画，保持柯基外形、花纹、场景光线与色彩统一。
全局视频提示词：保持首帧造型，动作自然连贯，禁止多余肢体、文字和水印。
默认模型：Seedance 2.0 mini
默认时长：10秒
默认画幅：9:16
角色参考图：豆豆_正面.png, 豆豆_侧面.png

### 分镜 1
首帧来源：本地图片
首帧图：01.png
视频提示词：柯基从草地上抬头，镜头缓慢推近。
生成次数：2
时长：10秒
画幅：9:16

### 分镜 2
首帧来源：提示词生成
分镜图提示词：同一只柯基站在木屋门口，清晨逆光。
视频提示词：柯基向前跑两步，耳朵自然晃动。

### 分镜 3
首帧来源：无
视频提示词：森林远景，薄雾缓慢流动。
```

`格式版本` 缺省时按 v1 解析，不支持的版本会停止导入。`角色参考图` 为可选项目级字段，可写多张并使用逗号分隔；导入时从同一素材文件夹解析，复制到应用数据目录并按 SHA-256 去重。生图前会按顺序上传角色参考图，全部出现缩略图后才追加“参考素材约束”并填写提示词；场景/风格参考图及视频阶段的项目参考图目前仍需手动处理。

## 技术栈

- Electron 44
- Vue 3 + TypeScript + Vite
- Electron/Node 内置 `node:sqlite`
- electron-builder

采用内置 SQLite，避免 `better-sqlite3` 等原生扩展带来的 Windows/macOS 多架构打包问题。

## 开发

要求 Node.js 24 或更高版本。

```bash
npm install
npm run dev
```

验证：

```bash
npm test
npm run typecheck
npm run build
```

打包：

```bash
npm run dist:win
npm run dist:mac
```

本地构建产物统一放在 `release/current/`。每次打包前会自动清理该目录，打包完成后只保留当前版本的安装包、压缩包和 `SHA256SUMS.txt`；历史版本由 GitHub Releases 保存。

macOS 安装包必须在 macOS 上生成；正式分发前还需要配置 Apple Developer ID、公证，以及 Windows 代码签名。

## 数据与安全

- 应用数据默认放在 Electron 的 `userData` 目录，界面设置页会显示实际路径，也可选择其他磁盘位置。
- 更改目录会在应用重启时复制完整数据，并保留旧目录作为备份；确认新目录正常后可手动删除旧目录。
- Cookie 仅由相应账号 Partition 管理，不写入 SQLite，不通过 IPC 返回给界面。
- 豆包远程页面启用 Chromium sandbox、关闭 Node Integration，并拒绝弹窗和非豆包顶层导航。
- 当前没有本地 HTTP API，控制台只通过最小化的 Electron IPC 调用主进程。
- 删除账号会清除对应 Partition 的本机浏览器数据；任务记录保留但解除账号关联。
